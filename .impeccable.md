## Design Context

### Users
Data analysts, administrators, and statisticians at IIEG (Instituto de Información Estadística y Geográfica de Jalisco). They work in an office all day — this is their primary tool, not an occasional-use app. They manage a 7-level statistical data catalog (proyectos → productos → fuentes → bases de datos → datasets → distribuciones → archivos). Expert users who reward familiarity and need minimal friction for repetitive tasks.

### Brand Personality
**Methodical, rigorous, approachable.** Institutional but not cold. Authoritative without being intimidating. The tool should feel like a well-organized archive run by people who care about data quality — not a consumer app, not a generic admin panel.

### Emotional Goals
**Efficiency and control.** Users should always know where they are in the hierarchy, what data they're looking at, and what actions are available. The interface should reduce cognitive load, not add to it.

### Aesthetic Direction
- **Theme**: Light mode (daytime office use, high ambient light)
- **Tone**: Precise, structured, quietly refined — like a well-typeset government publication, not a startup dashboard
- **Color**: Purple (#6E258B) brand identity with orange (#FF8300) accent. Dark purple sidebar (#2D0E42) as navigational anchor.
- **Anti-references**: No consumer/startup aesthetic, no glassmorphism, no hero metrics, no decorative flourishes that slow comprehension
- **Language**: Spanish (es-MX) throughout

### Design Principles
1. **Hierarchy first** — every screen must make the 7-level catalog structure instantly legible; navigation, breadcrumbs, and context cues are not optional
2. **Data density with breathing room** — tables and lists are the core surface; optimize for scanability: consistent alignment, clear typographic hierarchy, minimal visual noise
3. **Actions where you need them** — controls appear at the point of need (inline editing, contextual menus) rather than requiring navigation to separate screens
4. **Trust through consistency** — predictable patterns reduce cognitive load for daily users; every similar action must look and behave the same across the app
5. **Accessible by default** — WCAG 2.1 Level AA required; all interactive elements must be keyboard-navigable, all text must meet contrast requirements, all states (hover, focus, disabled, error) must be visually distinct
